# mugen: notes for agents working on it

mugen is Victor Taelin's UniiChat (one chat that never ends, its memory a
binary tree of one-line summaries) in Bend 2, as one terminal process. The
reference semantics are UniiChat's own sources, pinned as the flake input
`uniichat`; most modules name the UniiChat function they port (`Memory.fit`,
`Chat.take`), and comments follow its terse style. Read the module headers
first: each says what it owns.

## Layout

| Module | What it is |
|---|---|
| `bend/Sys.bend`, `bend/effs/mu.c` | C effects Base lacks (files by path, index slots, flock, isatty, kill, wall clock) |
| `Text`, `Json`, `Clock` | JS semantics: UTF-16 units, `\s`, `JSON.stringify`/`parse`, dates |
| `IMap`, `Tree`, `View` | U32 trie, tree arithmetic, views and their merge (pure) |
| `Store`, `Memory` | the logs and indexes; Memory.ts one to one |
| `Api`, `Compact` | a call's step, by curl (`--api`) or Claude Code's CLI (one turn); compaction jobs |
| `Code`, `Mcp` | Claude Code's CLI (`claude -p`, the default wire): argv, stream-json, the launch; our tools as an MCP server |
| `Ev`, `Tools`, `Diff`, `Agent` | events to the hub; local tools; unified diffs; the tool loop (`ag.api.run`), or Claude Code's call (`ag.cc.run`) |
| `Hub`, `Term`, `Main` | the chat (Server.ts Chat); the terminal off the full screen (lines, pipes); settings from the environment |
| `Keys`, `Edit`, `Pretty`, `Screen` | the full screen: raw keys (Shift-Enter, pastes, the mouse); the input, emacs keys and history; entries as rows (tool blocks, diffs, markdown); the screen itself |
| `Prompts` | generated by `tools/prompts.py` from the pinned UniiChat: never edit |

## Tests (all are flake checks: `nix flake check`)

- `memdiff`: Memory.bend against UniiChat's Memory.ts, step for step
  (`tools/memdiff/run.sh N SEED`; both sides must print the same trace and
  leave byte-identical logs). Run it after any change to Memory, View, Store,
  Tree, Text or Json.
- `merge`: View.merge against Memory.merge on random views.
- `goldens`: Text/Json/Diff and the local tools against UniiChat's own code.
- `api`: Api/Compact against `tools/fakeapi.ts` (a stand-in for curl).
- The full screen has no flake check (it needs a terminal); drive it in a
  tmux server of its own: `tmux -L t new-session -d -x 110 -y 40 "MUGEN_DIR=...
  MUGEN_CLAUDE=... run/mugen"`, then `send-keys` (`S-Enter`, `-H` bytes for
  the mouse) and `capture-pane -p`. Pure modules run fast on the JS lane
  (`bend bend/tests/PrettyShow.bend`, `EditShow.bend`).
- `scenarios`: the app in pipe mode on both wires (`WIRE=claude`, the
  default, against `tools/fakeclaude.ts`, a stand-in for Claude Code's CLI
  that plays fakeapi.ts's scripts and calls our MCP server; `WIRE=api`
  against `tools/fakeapi.ts`), with the same `expect` for both
  (`tests/scenarios/*`: `input` or `run`, the fake's scripts, `expect`,
  `expect.<wire>` if a wire differs, optional `check`).

Outside nix: `nix develop` gives `bend`, `bun`, `jq` and `$UNIICHAT`; build a
test with `bend bend/tests/X.bend -o run/x` (run/ is ignored by git).

## Bend 2 traps (each cost real time here)

- **`Bool.pick` evaluates both arms, fully.** A recursive call in an arm is
  always made (exponential if both arms recurse; a scan that never stops if
  the recursion is meant to end). Worse, an arm holding a long structure
  that shares a tail with the other copies that whole tail: `tl.split` took
  48 s on 60 KB until its choice became a match. Branch with `match` on a
  Bool (or a Nat verdict) passed as a parameter; keep `Bool.pick` for small
  values.
- **No mutual recursion.** Loops are one function; "what comes next" is a
  parameter (a Nat verdict, or a small Data type like `ag.Next`). A helper
  that calls back into its caller is refused ("unfilled law is a dead claim").
- **Defs before callers.** `python3 tools/order.py --fix FILE` reorders.
- **`match` only on parameters, in binder order, before any `let`.** Give a
  computed value its own def (`hb.take` → `hb.take.on(hb.turn(s), ...)`).
- **`+x` marks a Data value used more than once.** `python3 tools/plus.py
  FILE` adds them as the checker asks. Types (pairs `A & B`, functions,
  `List<String>` from IO.args) can't be `+`: destructure pairs in a helper's
  `match`, never with `+` inside a tuple pattern, and pass Chans (Data) where
  a callback would be needed.
- **Annotate constructor literals bound by `+x = ...`** (`{ap.Ask{...} :
  ap.Ask}`) when the checker can't infer them.
- **`IO.now` is monotonic** (time since boot); dates use `mu.wall`.
- **Lists of pairs aren't Data**: use a record (`df.P{a, b}`).
- **Strings are lists of code points**: a lone surrogate can't exist, so
  where JS would keep half a pair we hold U+FFFD (the memdiff harness
  compares zooms through `toWellFormed`).
- **Literals**: `"\u{1B}"`, not `"\x1b"`; dotted names (`a.b`) are never
  binders.
- **Pairs are Type**: `+p = f(x)` fails when f answers `A & B` ("expected
  Data"); answer a small Data record instead (`pp.Two{a, b}`).
- **`[]` is no pattern in a match of many scrutinees**: write `Nil{}`
  (`case Nil{} _:`).
- **A `do` block's let needs its type**: `+x : T = v`.
- **`Bool.pick` again**: on the screen it is a render in an arm that costs
  (every block drawn anew at each key); a verdict parameter and a `match`
  (`pp.body.k`, `sc.attach`) keep the work to the arm taken.

## Claude Code's wire

- A chat call is a background `claude -p` (Code.bend `cc.launch`): stdin is
  the FIFO `run/<who>.cc.in`, events go to `.cc.out` (read by polling, never
  a blocking open), MCP goes through `.cc.mcp.in`/`.cc.mcp.out` and a relay of
  `tail` and `cat`, and the group's leader is in `.cc.pid`. Don't reuse
  `run/<who>.out`, `.code` or `.pid`: the shell tool owns them.
- Our messages carry one cache mark (the first marked block). Claude Code
  adds three (its identity line, the system prompt, the last message), which
  makes the four the API allows. Marks are `ttl: 1h`, matching Claude Code's
  on a plan (`CLAUDE_CODE_PROMPT_CACHE_TTL=1h`).
- What Claude Code does with stream-json input (marks kept, mid-turn messages
  after tool results, ids said back with `--replay-user-messages`) is its
  internal behaviour. Re-check it after an upgrade against a local capture
  server (`ANTHROPIC_BASE_URL`, a dummy key).

## Conventions

- Every def in a module is prefixed (`me.`, `hb.`, ...): a program's defs share
  one namespace.
- State is Data with accessor and `with.*` setter defs; events go through the
  hub, which is the only writer of the logs. stdout is the hub's off the full
  screen; on it, the screen's (Screen.bend), which the hub tells what to show
  (sc.Put, sc.State) and which sends it the lines typed (ev.Line).
- The JSONL records match UniiChat byte for byte (`memdiff` checks), so either
  program opens the other's data dir.
- Nix sees only git-tracked files: `git add` new files before `nix build`.
